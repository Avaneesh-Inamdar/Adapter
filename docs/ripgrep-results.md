# ripgrep 15.2.0 on Adapter

Status: Windows-side execution demonstrated; reference-Mac equivalence not
established. This is the second unmodified real binary in the regression set,
after jq 1.8.2.

`tools/fetch_ripgrep.py` checks the archive and member sizes and hashes, extracts
only that member in memory, re-verifies the binary, writes it under ignored
`tests/fixtures/generated/reference/`, and records
`provenance-ripgrep.json`. It is not rebuilt and no Windows ripgrep participates.
The artifact is a separate third-party fixture, not part of the Apple input
corpus in `docs/reverse-engineering/apple-inputs/targets.json`.

## Static shape

`adapter-inspect` reports a thin little-endian x86-64 Mach-O executable with two
direct dependencies: `/usr/lib/libiconv.2.dylib` (no referenced imports) and
`/usr/lib/libSystem.B.dylib`. The symbol table contributes 132 undefined names;
131 are API imports with adapters and `dyld_stub_binder` is the eager-binder
diagnostic. Coverage regenerated by `tools/update_progress.py` records
131 / 131 (100%) for this target. See
[the import inventory](progress/README.md) and
[the target evidence](reverse-engineering/ripgrep-target.md).

## Executed behavior

`tests/integration/test_ripgrep.py` runs the pinned binary through
`adapter-run.exe` in a fresh temporary directory. All 11 methods pass in debug
and release:

| Test | Observed Windows-side behavior |
| --- | --- |
| `test_version_and_help` | exact version/features prefix and help text |
| `test_literal_and_regex_search` | line numbers, literal/regex matches and context |
| `test_recursive_ignore_and_hidden` | gitignore exclusion, hidden-file opt-in, `.git` exclusion |
| `test_json_stream` | parseable match events, line numbers, submatch offsets and summary |
| `test_pcre2_and_unicode` | PCRE2 capture matching and a UTF-8 pattern |
| `test_stdin_is_preferred_over_cwd` | piped stdin search instead of `.` |
| `test_binary_detection_and_text_mode` | binary-file message by default; raw bytes with `-a` |
| `test_large_file_memory_map` | match in a 2 MiB file through the mmap path |
| `test_multithreaded_directory_search` | 40 files listed by the worker pool |
| `test_exit_codes_and_regex_errors` | exit 0/1 for match/no-match and 2 with a parse diagnostic |
| `test_preprocessor_spawn_fails_cleanly` | `--pre` exits 2 with "preprocessor command could not start" |

The preprocessor result is intentional: `fork`, `execvp`, `waitpid` and
`posix_spawnp` report ENOSYS/ECHILD because the runtime owns one guest process
per host process. No child was started and the failure is clean rather than a
crash.

## Adapter surface added for this target

- Descriptor and directory work: `fcntl` (`F_DUPFD_CLOEXEC`), `fdopendir`,
  `dirfd`, Darwin-layout `dirent` and guarded `stat`/`lstat`/`fstatat`.
- Memory: `MAP_FIXED` in-place mapping, file-backed `mmap`, corrected
  `posix_memalign`/aligned realloc block sizing, `memset_pattern16`.
- Threads: validated 64-byte stack-size attributes, current-thread stack bounds,
  thread names/IDs, normal and recursive mutexes over SRWLOCK.
- Startup/introspection: `___chkstk_darwin`, dyld image count/header/name/slide,
  `dlsym`, `__tlv_atexit`, `_SC_HOST_NAME_MAX` and the remaining signals,
  process stubs and dispatch semaphores imported by the binary.

## Boundaries and unknowns

- All evidence is Windows-side. No reference Mac has run this artifact.
- Signal handlers, masks and alternate stacks are recorded, never delivered.
- Condition variables, cancellation and errorcheck/adaptive mutexes are absent.
- The preprocessor path is a failure-path observation, not spawn support.
- Common search paths are covered; every ripgrep option and error path is not.
- Locale/timezone behavior and very large or unusual file layouts are not
  exhaustively compared with macOS.
